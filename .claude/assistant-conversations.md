# Assistant conversations

Spec: `docs/superpowers/specs/2026-10-11-assistant-conversation-history-design.md`. Plans: `docs/superpowers/plans/assistant-conversation-history/`.

## Storage

- `<workspace>/assistant/conversations/<id>.yml`, one file per conversation, `<id>` a lowercase UUID. `<workspace>/assistant/.gitignore` holds `*` (created with `create_new`, never overwritten, a failure only logged).
- Rocket-private, not OpenCollection: no file under `collections/` and no key in `opencollection.yml`, `folder.yml`, request, environment or `workspace.yml` files. Collections are referenced by `opencollection.yml` uid only.
- Keys are snake_case (`ConversationRecord` in `rocket-acp`, no `rename_all`). IPC DTOs in `src-tauri/src/commands/assistant_conversations.rs` are camelCase.
- Caps: 50 conversations (oldest `updated_at` evicted, never the one just saved), 500 messages (newest kept), 16 KB per text field (`TEXT_CUT_MARKER`). Unparseable, other-version or misnamed files are skipped by `list` with a warning.

## Saving

- `start_workspace_assistant` calls `ConversationService::pin_session(session_id)`. The pin holds `pinned()` repositories of the workspace active at start; `save_conversation(session_id, ...)` writes there even after a switch. 16 pins are kept. The McpToolService pin is not used, because it is dropped at session end, before the final save.
- Masking: secret variable values of the pinned workspace (global environments, collection variables and initial values, collection environments, folder and request variables of every request kind, nested folders included) are replaced with `••••••` by `mask_secret_text`, before the caps. The input is bounded first: a payload over `MAX_INPUT_TEXT_BYTES` (2 MB of text) is refused, and only the newest 500 messages are masked. The title comes from the first user message, masked.
- Fail closed: any unreadable source refuses the save with a generic `InvalidInput` and writes nothing: a keychain read error other than "no entry" (`SecretStore::get_strict`; the lenient `get` still reads a locked keychain as a miss for every other caller, and "no entry" stays a miss in both), a corrupt environment file, an unusable environment name, a request file that does not parse, an unreadable `folder.yml` or settings file, and a directory with legacy collection files whose migration fails. This uses the strict reads `SecretStore::get_strict`, `EnvironmentRepository::list_strict`, `CollectionRepository::list_strict` and `CollectionRepository::get_strict`. Their trait defaults delegate to the lenient read (fail-open), so any new implementer or decorator must override them; the production ones do. Plain directories under `collections/` with no collection files are skipped. The log line names the scope and the error kind only, never the error text or a value.
- Limits of the masking (v1): values shorter than 6 characters (`MIN_REDACTION_LEN`) are not masked; only the exact value is matched, not case, base64 or other encodings; overlapping secrets can leave the tail of one visible; vault values are not fetched; externally linked collections are not scrubbed, because only collections under `<workspace>/collections` are walked (the same list the assistant's tools use).
- Side effect: the walk calls `CollectionRepository::list_strict` and `get_strict`, which auto-migrate a legacy JSON collection to YAML on first read, like `get`. A save can therefore migrate a legacy collection.
- The pin is dropped when the session fails to start (`unpin_session`). It is not dropped at session end, because the final save runs after cleanup; it ages out with the 16-pin cap.
- Every save walks every request file of the workspace, once per finished turn (debounced in the frontend).
- Events carry ids only: `assistant-conversation-saved`, `assistant-conversation-deleted`, `assistant-conversations-cleared`.

## Frontend

- `assistant-store.conversationId` is made at the first user message of a session (`crypto.randomUUID()`), cleared by `beginSession` and `reset`.
- `startConversationSaver` (`src/lib/assistant/conversation-saver.ts`, started by `useAssistantEventBridge`) saves 500 ms after a turn ends, and at once at session end and panel close. Saves are chained, so they reach the backend in order. Streaming segments are never saved, and a chat without an agent reply is not saved. The session-end save takes proposals from the previous state, because `endSession` and a fatal `failMessage` drop them in the same update. A failed save shows one toast per conversation.
- `toStoredMessages` (`conversation-snapshot.ts`) places proposals by their anchor (`src/lib/assistant/timeline.ts`).
- History: the panel's History button shows `AssistantHistoryView` (list, delete, Clear all with a confirm). `AssistantConversationView` renders stored messages with `ChatItem`; stored proposals are plain lines with no actions. The view reloads on the three events and on a workspace switch, which also closes the open conversation.
- Keychain unavailable: a locked or broken keychain makes `SecretStore::get_strict` fail, so that conversation is not saved (the user sees the save-failed toast) rather than saved with unmasked secrets. A missing keychain entry is a normal miss and does not block a save.
- Where the code lives: `rocket-acp` `conversation.rs` (model, caps, trait), `rocket-app` `ConversationService` and `conversation_secrets.rs` (masking), `rocket-infra` `FsConversationRepo` (files), `src-tauri/src/commands/assistant_conversations.rs` (IPC), frontend `src/lib/assistant/` (`conversation-saver.ts`, `conversation-snapshot.ts`, `replay-preface.ts`, `assistant-session.ts`) and `src/components/assistant/` (`AssistantHistoryView.tsx`, `AssistantConversationView.tsx`).

## Continue (replay)

- Continue (read-only view footer) calls `continueConversation(record, agentConfigId)`. A conversation of another workspace is refused (`CONTINUE_WORKSPACE_MISMATCH`), both before and after the live session ends, so a workspace switch during the await cannot start it. A live session ends first (and saves), then `startAssistant(agentConfigId, 'ask', { fromId, preface })`. Always Ask mode. A deleted agent config leaves the picker empty and Continue disabled.
- A throw before the start (for example from `buildReplayPreface`) shows the toast "Could not continue this conversation." and returns to the History view; nothing is logged. A failed start shows its error in the Start view, and Retry there restarts with the same mode and replay seed (read from the error session and `replay` in the store). Only a failed start qualifies, which has an empty session id. A session that died mid-chat restarts in the default mode with no seed, so the old preface is never sent again.
- `buildReplayPreface` (`src/lib/assistant/replay-preface.ts`): header, `<previous-conversation>` frame, newest messages that fit in 12,000 characters (`DEFAULT_REPLAY_LIMITS`, the whole block counts), oldest first, a marker (`replayDroppedMarker`) when older ones were left out, the end of an oversized newest message. Each body is capped at 3,000 characters (`PER_MESSAGE_MAX_CHARS`). Tools and proposals are one-line title or summary plus status; notices and tool results never appear.
- Escaping: stored text is quoted history. Line breaks are normalized, control characters are removed, `&` and `<` are escaped (so stored text cannot hold the frame tags), and continuation lines are indented so no stored line starts at column 0.
- `sendAssistantMessage` puts the preface in front of the first prompt only (`replay.sent`, set after a successful send, so a failed first send keeps it). The chat and the saved conversation keep only the typed text, so prefaces never nest. The new conversation saves with `continued_from`; the old one is not changed. There is no backend limit on prompt text; the composer only shows the size (`replaySizeHint`).
- The History list shows `Continued from "<title>"` under a continued conversation, or `Continued from an earlier conversation` when the source is gone.
