# Manual test: rok.grpc

Checks of `rok.grpc.run` and `rok.grpc.call` in the real app. Written 2026-11-12 from the source. None of these steps were run when this file was written. Feature doc: `docs/features/rok-grpc.md`.

## Server

The checks use the `Greeter` service of `crates/rocket-infra/test-fixtures/grpc/greeter.proto` (package `demo.greeter.v1`, imports `common.proto`). The repo has no standalone server binary. The fixture server (`crates/rocket-infra/src/grpc/test_server.rs`) runs only inside `cargo test`, in process. So run any server that implements this proto on `localhost:50051`, plaintext, with the behaviour of the fixture server (decided by the request `name`):

- `SayHello` replies `hello <name>`. A name `fail` answers NOT_FOUND with the trailer `x-detail: gone`. A name `slow` replies after 2 seconds. A name `whoami` replies with the `authorization` metadata, and `trace` with the `x-trace` metadata.
- `ListGreetings` streams 3 replies `<name>-0` to `<name>-2`.
- `CollectNames` returns one reply with the names joined by `,` and `sequence` set to the count.
- `Chat` echoes each input as `echo <name>`.

Checks 9 and 10 need two extra behaviours: a name `many` that makes `ListGreetings` stream 1500 replies, and a name `hang` that makes `ListGreetings` send one reply and then keep the stream open. If your server has none, skip those two.

## Setup

A collection `api` (Developer mode on, workspace guard off unless a check says otherwise):

- Copy `greeter.proto` and `common.proto` to `<collection>/protos/`.
- A gRPC request `greeter/say-hello.yml` (unary, `demo.greeter.v1.Greeter/SayHello`, URL `grpc://localhost:50051`, proto `protos/greeter.proto`, message `{"name": "saved"}`). Create `greeter/list-greetings`, `greeter/collect-names` and `greeter/chat` the same way for the other three methods.
- A request `A` (HTTP, any URL, for example `https://httpbin.org/anything`) to hold the scripts. Put each script below in its pre-request script and send `A`, then read the Console and the script result (use `console.log(JSON.stringify(r))`).

## Checks

1. **Saved unary.** `const r = await rok.grpc.run('greeter/say-hello.yml'); console.log(JSON.stringify(r))`. See `status` `{code: 0, name: "OK", message: ""}`, `message` `{message: "hello saved", ...}`, `messages` with one item, `headers` and `trailers` as plain objects with lowercase keys, `truncated` false. The Console has a line `rok.grpc greeter/say-hello.yml -> OK`, without message content. Repeat with `greeter/say-hello` (no extension): same result.
2. **Saved with options.** `rok.grpc.run('greeter/say-hello', { message: { name: 'ann' }, metadata: { 'X-Trace': 'a' } })`. See `hello ann`. With a `trace` name and the metadata, the reply holds `a` (the key was lowercased).
3. **Ad hoc unary.** `rok.grpc.call({ url: 'grpc://localhost:50051', service: 'demo.greeter.v1.Greeter', method: 'SayHello', protoFile: 'protos/greeter.proto', message: { name: 'ann' } })`. See `hello ann`, status OK. The URL `localhost:50051` (no scheme) works the same.
4. **Server stream.** `rok.grpc.run('greeter/list-greetings', { message: { name: 'ann' } })`. See 3 messages in order (`ann-0`, `ann-1`, `ann-2`), `message` equal to the first, status OK.
5. **Client stream.** `rok.grpc.run('greeter/collect-names', { messages: [{ name: 'a' }, { name: 'b' }, { name: 'c' }] })`. See one message with `a,b,c` and `sequence` 3.
6. **Bidirectional.** `rok.grpc.run('greeter/chat', { messages: [{ name: 'a' }, { name: 'b' }] })`. See two messages `echo a`, `echo b`, then status OK (the request side is closed after the last input).
7. **Input rules.** `rok.grpc.run('greeter/say-hello', { message: {}, messages: [{}] })` rejects with a text containing `give message or messages, not both` (the full text is `rok.grpc.run: give message or messages, not both`, a TypeError from the script layer). Two messages to the unary request reject with `... takes one input message, got 2`. A message with a field the proto does not have, for example `{ nope: 1 }`, rejects with `message 0 does not fit the request type`, and the text does not quote the value. `rok.grpc.run('greeter/nope')` rejects with `invalid request path - greeter/nope`. A path of an HTTP request (`A`) rejects with `is not a gRPC request`.
8. **Server status and trailers.** Send a message with `name: 'fail'`. The Promise resolves (no throw). See `status.name` `NOT_FOUND`, `trailers['x-detail']` `gone`, no messages.
9. **Cap, 1000 messages.** `rok.grpc.run('greeter/list-greetings', { message: { name: 'many' } })` against a server that streams 1500. See `messages.length` 1000, `truncated` true, `status` `{code: 8, name: "RESOURCE_EXHAUSTED", message: "the response was cut at the size limit"}`. The script keeps running. (The 10 MiB cap works the same way, with a server that sends large messages.)
10. **Time limit.** (Needs the `hang` behaviour from the top of this file.) `rok.grpc.run('greeter/list-greetings', { message: { name: 'hang' }, timeoutMs: 1500 })`. After about 1.5 s see `status` code 4 `DEADLINE_EXCEEDED` with the text `the call did not finish within 1500 ms`, `messages` holding the one reply that arrived, `truncated` false. Also try `name: 'slow'` with `timeoutMs: 500` on the unary request: DEADLINE_EXCEEDED, no messages. `timeoutMs: 0` or `-5` rejects with `timeoutMs must be a finite number greater than 0`.
11. **Callback form.** `rok.grpc.run('greeter/say-hello', (err, r) => console.log(err, r && r.status.name))` prints `null OK`. With a bad path the callback gets the error and `null`. The `call` form with a callback works the same. `await` on the returned Promise resolves to the callback's return value.
12. **Safe mode refusal.** Switch the collection to Safe mode and send `A`. Both `run` and `call` reject with `gRPC calls need Developer mode` (prefixed `rok.grpc.run:` or `rok.grpc.call:`). No request reaches the server (check the server log). Switch back to Developer mode.
13. **Blocked host.** In the workspace security popover, turn on "Block script redirects to internal hosts". Make the HTTP request `A` use a non-local URL such as `https://httpbin.org/anything`. Run `rok.grpc.call({ url: 'grpc://127.1:50051', ... })` (also try `grpc://2130706433:50051`, `grpc://0x7f.1:50051`, `grpcs://localhost:50051` and the saved request after pointing its URL at `grpc://127.1:50051`). Each rejects with a text containing `blocked: script redirected request to internal host` (for example `rok.grpc.call: Invalid input: blocked: ...`). The server log shows no connection and no reflection call. With the toggle off, the same call to `grpc://127.1:50051` goes through. A call to a name that does not resolve is not blocked by the guard, because it checks names, not resolved addresses.
14. **Proto outside the collection, absolute path.** `rok.grpc.call({ ..., protoFile: '/abs/path/to/greeter.proto' })` rejects with a text containing `the proto path must be relative to the collection, use / separators and have no '..' part`. Also try `../greeter.proto`, `protos/../protos/greeter.proto`, `~/greeter.proto` and `protos\\greeter.proto`: all reject the same way.
15. **Proto outside the collection, symlink.** Put `greeter.proto` and `common.proto` in a folder outside the collection. In `<collection>/protos/` make a symlink `link.proto` to that file. `protoFile: 'protos/link.proto'` rejects with `is outside the collection folder`. `protoFile: 'protos'` rejects (`is not a file`), and `protos/missing.proto` rejects (`could not resolve proto file`). A saved request whose `protoFilePath` is an absolute path rejects under `rok.grpc.run` the same way, while the gRPC pane still sends it.
16. **Connect failure.** Stop the server. `rok.grpc.run('greeter/say-hello')` resolves (no throw) with `status` `{code: 14, name: "UNAVAILABLE", message: "could not connect to the server"}` and no messages. A saved request with a proto path and a wrong port gives the same. An ad hoc call without a reachable server also resolves UNAVAILABLE.
17. **Secret variable in a saved request.** Add a secret variable `token` with the value `s3cr3t-value` in the environment. Set the saved request's metadata `authorization` to `Bearer {{token}}`, then call it with the `whoami` name and print the result. The server receives the real value (the reply holds `Bearer s3cr3t-value`, which is the server's own echo). Then break the call on purpose (a message `{ nope: 1 }`, or a wrong method) and look at the rejection text and the Console. Neither holds `s3cr3t-value`.
18. **Ad hoc sends no collection auth.** Give the collection a bearer auth `collection-token` and a default header `x-default: 1`, and give a saved request auth `inherit`. Against the `whoami` name: `rok.grpc.run` of the saved request returns a reply with the inherited token. `rok.grpc.call(...)` to the same server returns an empty `authorization` (no token) and the server log shows no `x-default` header. Adding `metadata: { authorization: 'Bearer x' }` to the `call` makes the reply `Bearer x`.
19. **Variables and runtime vars.** The saved request URL is `grpc://{{host}}`, with `host` an environment variable `localhost:50051`. `rok.grpc.run` connects. A script that runs `rok.setVar('who', 'zed')` first and a message `{ name: '{{who}}' }` replies `hello zed`. A script that runs `rok.setEnvVar('host', 'localhost:9')` and then `rok.grpc.run` still uses the old host (env writes of the same script are not seen).
20. **Nested slot.** In a loop, start 20 calls at once: `await Promise.all(Array.from({length: 20}, () => rok.grpc.run('greeter/say-hello', { message: { name: 'slow' } })))`. The calls that start while 16 are active reject with `too many nested requests running (limit 16)`. A single call afterwards works.
21. **Agent tool-call path.** In the workspace assistant (Agent mode), use `run_request` on a request that calls `rok.grpc.run`. The script rejects with `gRPC is not available here`. This is the known limit R-94.
