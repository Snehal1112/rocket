# UUID Identity for Collections, Folders, and Requests — Design Spec

**Date:** 2026-03-25
**Status:** Approved

## Problem

Collections, folders, and requests have no stable unique identifier. Tab matching relies on filename-based paths which break on rename. Multiple workarounds (findTabBySource, fileName field) patch the symptoms but don't solve the root cause.

## Solution

Add a `uid: String` (UUID v4) to every entity. The uid is the stable identity — it survives renames, moves, and filename changes.

## Changes

### 1. Request — `uid` field in JSON

Add `uid: String` to `Request` struct in `crates/rocket-collection/src/request.rs`.

```rust
pub struct Request {
    #[serde(default = "generate_uid")]
    pub uid: String,
    pub name: String,
    pub method: HttpMethod,
    pub url: String,
    pub headers: Vec<Header>,
    pub body: Option<Body>,
    #[serde(default)]
    pub auth: Auth,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub file_name: Option<String>,
}

fn generate_uid() -> String {
    uuid::Uuid::new_v4().to_string()
}
```

- Persisted in the `.json` file alongside other fields.
- `Request::new()` generates a UUID v4.
- `#[serde(default = "generate_uid")]` — old JSON files without `uid` get one on deserialization.
- `build_folder_tree`: after deserializing a request, if `uid` was generated by serde default (empty check not needed since default always generates), write the file back once to persist it. Use a flag to avoid writing on every read.
- Add `uuid` dependency to `rocket-collection/Cargo.toml`.

### 2. Folder — `.uid` file per directory

Add `uid: String` to `Folder` struct in `crates/rocket-collection/src/folder.rs`.

```rust
pub struct Folder {
    pub uid: String,
    pub name: String,
    pub items: Vec<CollectionItem>,
}
```

Each folder directory contains a hidden `.uid` file with just the UUID string:
```
~/.rocket-api/collections/my-api/Payments/.uid  → "a1b2c3d4-..."
~/.rocket-api/collections/my-api/Payments/Refunds/.uid → "e5f6g7h8-..."
```

- Simpler than a centralized hashmap in collection.json.
- Survives folder renames (the `.uid` file moves with the directory).
- No synchronization issues — each folder owns its own identity.
- `build_folder_tree`: reads `.uid` from each directory. If missing, generates one and writes it.
- `create_folder`: writes a `.uid` file immediately after `mkdir`.
- The `.uid` file is excluded from `is_request_file()` (already excluded — starts with `.`).

### 3. CollectionSummary — `uid` field

Add `uid: String` to `CollectionSummary` in `crates/rocket-collection/src/summary.rs`.

```rust
pub struct CollectionSummary {
    pub uid: String,
    pub name: String,
    pub path: String,
    pub request_count: usize,
}
```

- The collection uid is stored in `.uid` file at the collection root directory (same pattern as folders).
- `list()` reads `.uid` from each collection dir. If missing, generates and writes.

### 4. CollectionSettings — unchanged

`CollectionSettings` does not need uid/folderUids fields. UIDs are stored in `.uid` files, not in `collection.json`.

### 5. Frontend — tab ID uses uid

**tauri-api.ts types:**
- `Request` gets `uid: string`
- `Folder` gets `uid: string`
- `CollectionSummary` gets `uid: string`

**Tab matching:**
- Tab `id` = request `uid` (not `collection/filename`)
- `openTab` matches by `tab.id` (which is now the uid) — simple, stable
- Remove `findTabBySource` — uid matching is sufficient
- `source` still has `collection` + `path` for file operations

**CollectionsSidebar:**
- `RequestNode` uses `item.uid` as `tabId`
- `handleNewRequest`: the `save_request` Tauri command returns the request with a uid. Use it as tab id.
- Active request highlight matches by uid

**SaveToCollectionDialog:**
- After save, use the request's uid as the tab id.

### 6. Tauri command changes

`save_request` should return the saved `Request` (including its uid) instead of `void`:
```rust
pub fn save_request(...) -> Result<Request, DomainError>
```

This gives the frontend the uid immediately after save, without needing a separate fetch.

### 7. Migration

When the app reads old data without UIDs:
- Requests: `serde(default = "generate_uid")` generates on deserialization. `build_folder_tree` writes the file back once to persist.
- Folders: `build_folder_tree` creates `.uid` if missing.
- Collections: `list()` creates `.uid` if missing.
- One-time cost on first load after upgrade.

### 8. `.uid` file format

Plain text file containing a single UUID v4 string, no newline:
```
a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

- Hidden file (starts with `.`) — already excluded by `build_folder_tree`'s dot-file skip.
- Not a `.json` file — not matched by `is_request_file()`.
