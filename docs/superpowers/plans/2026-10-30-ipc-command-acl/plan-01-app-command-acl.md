# App command ACL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Only the local app page in the `main` window can call Rocket's own Tauri commands. A remote page in the `oauth2-auth` window, or any other window or origin, gets a "not allowed" rejection.

**Architecture:** Turn on Tauri's app ACL by giving `tauri-build` an `AppManifest` with every app command. One text file, `src-tauri/app-commands.txt`, is the only command list. `build.rs` reads it, autogenerates an `allow-<cmd>` permission per command, and writes a `main-window-commands` permission set that the existing `default` capability (windows `["main"]`, no `remote` key) grants. A unit test keeps the file in sync with `generate_handler!`, and IPC tests on `tauri::test::MockRuntime` pin the allow and deny cases.

**Tech Stack:** Rust, Tauri 2.10.3, tauri-build 2.5.6 (`src-tauri` crate, package `rocket`).

**Spec:** The security finding raised while closing the Low items of issue #115 (https://github.com/Snehal1112/rocket/issues/115), merged in `199adc61`. The finding has no spec of its own, so the decisions below are this plan's own calls. Facts checked in the cargo registry sources:
- `tauri-2.10.3/src/webview/mod.rs:1802`: app commands are ACL-checked only when `has_app_acl_manifest` is true.
- `tauri-build-2.5.6/src/acl.rs:264-320`: `AppManifest::commands` writes `./permissions/autogenerated/<cmd>.toml`, and the default glob `permissions/**/*` loads the app's permission files.
- `tauri-utils-2.8.3/src/acl/build.rs:290-313`: the identifiers are `allow-<cmd with _ replaced by ->`.

## Global Constraints

- Touch only `src-tauri/build.rs`, `src-tauri/app-commands.txt`, `src-tauri/capabilities/default.json`, `src-tauri/.gitignore`, `src-tauri/src/lib.rs` (module declaration only), the new test module, and the docs named in Task 2. No command code changes.
- Cargo commands carry `-j4` and `-p rocket`: `cargo check -j4 -p rocket` and `cargo test -j4 -p rocket --lib ipc_acl`. Never a workspace run.
- No unwrap calls in production code. `build.rs` and tests may use `.expect("...")` with a clear message.
- Plugin permissions in `default.json` stay exactly as they are.
- `src-tauri/permissions/` is generated by the build. Gitignore it; never hand-edit it.
- Code comments are short full sentences ending with a period.

## Decisions (this plan's calls)

- Root fix only (an app ACL), not the "cut IPC from the OAuth window" partial fix. Tauri 2 has no builder switch to remove IPC from one window. With the ACL on, a window with no capability gets nothing, so the root fix also closes the OAuth window.
- The `oauth2-auth` and `oauth2-auth-clear` windows get no capability. They need none: the OAuth callback is caught in Rust by `on_navigation` (`src-tauri/src/commands/oauth2.rs:96,499`).
- No `remote` entry in any capability. The `main` window only ever loads the local app.
- One command list file instead of 268 entries hand-copied into both `build.rs` and a TOML set. `build.rs` writes the set from the file.
- A missed command shows up as a failing sync test, not as a broken button at runtime.

## Review Focus

1. A remote page (`https://idp.example.com`) in `oauth2-auth` calls an app command: rejected. Pinned by `remote_page_in_oauth_window_cannot_invoke_app_commands`.
2. The local app page in `main` calls an app command: allowed, so the app keeps working. Pinned by `main_window_local_page_can_invoke_app_commands`.
3. The `main` window after it navigates to a remote page: rejected, because the capability is local-only. Pinned by `remote_page_in_main_window_cannot_invoke_app_commands`.
4. A command added to `generate_handler!` but not to `app-commands.txt`, or the reverse: the sync test fails and names it. Pinned by `app_commands_file_matches_generate_handler`.
5. The OAuth embedded sign-in still completes after the change: a manual check in Task 2, because the callback path is Rust-only and cannot be driven on `MockRuntime`.

## File Structure

- Create `src-tauri/app-commands.txt`: one command name per line (the last path segment of each `generate_handler!` entry), sorted, no duplicates, `#` comments allowed.
- Modify `src-tauri/build.rs`: read the file, write the permission set, call `tauri_build::try_build` with the `AppManifest`.
- Modify `src-tauri/capabilities/default.json`: add `"main-window-commands"`.
- Create `src-tauri/src/ipc_acl_tests.rs` (`#[cfg(test)]`): the sync test and the IPC tests. Declare it in `src-tauri/src/lib.rs` as `#[cfg(test)] mod ipc_acl_tests;`.
- Modify `src-tauri/.gitignore`: add `/permissions/`.

- [ ] **Step 1: Write the command list and the sync test**

Fill `src-tauri/app-commands.txt` with the last path segment of every entry in the `tauri::generate_handler![...]` block of `src-tauri/src/lib.rs:985` (268 entries today). Then add to `ipc_acl_tests.rs`:

```rust
#[test]
fn app_commands_file_matches_generate_handler() {
    let file = parse_command_file(include_str!("../app-commands.txt"));
    let handler = parse_generate_handler(include_str!("lib.rs"));
    let missing: Vec<_> = handler.difference(&file).collect();
    let extra: Vec<_> = file.difference(&handler).collect();
    assert!(missing.is_empty(), "add to app-commands.txt: {missing:?}");
    assert!(extra.is_empty(), "remove from app-commands.txt: {extra:?}");
}

#[test]
fn app_commands_file_is_sorted_and_unique() { /* lines (minus comments and blanks) equal their sorted, deduped copy */ }
```

`parse_command_file(&str) -> BTreeSet<String>` skips blank and `#` lines. `parse_generate_handler(&str) -> BTreeSet<String>` takes the text between `generate_handler![` and the matching `]`, splits on `,`, trims, skips empty and `//` lines, and keeps the segment after the last `::`.

- [ ] **Step 5: Turn on the app ACL in `build.rs`**

`fn main()` does three things:
- It reads `app-commands.txt` with the same rules as `parse_command_file`, and prints `cargo:rerun-if-changed=app-commands.txt`.
- It writes `permissions/main-window-commands.toml` (with `create_dir_all`) containing one `[[set]]`: `identifier = "main-window-commands"`, a one-line `description`, and `permissions = ["allow-<cmd with _ as ->", ...]`. It starts with a `# Generated by build.rs from app-commands.txt. Do not edit.` header.
- It calls `tauri_build::try_build(tauri_build::Attributes::new().app_manifest(tauri_build::AppManifest::new().commands(cmds)))`, followed by `.expect("tauri-build failed")`.

`commands` needs `&'static [&'static str]`, so leak the parsed `Vec<String>` (`Box::leak`). That is fine in a build script. Add `"main-window-commands"` as the last entry of `permissions` in `capabilities/default.json`, and add `/permissions/` to `src-tauri/.gitignore`.

Expected: the check is clean. All six `ipc_acl` tests PASS. `git status` shows no files under `src-tauri/permissions/`.
